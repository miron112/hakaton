## Роль и контекст

Ты — опытный Python-разработчик. Мы — команда на хакатоне, решаем кейс издания СИА-ПРЕСС (siapress.ru), независимого городского интернет-издания Сургута и Югры.

**Проблема:** важные новости появляются в десятках источников (ведомства, муниципалитеты, организации, СМИ, публичные Telegram- и VK-каналы) в разное время и в разных форматах. Небольшая редакция не может проверять всё вручную.

**Задача:** сделать работающий прототип сервиса, который каждые 15 минут проверяет заданные источники, находит новые сообщения, отбирает значимые для Сургута (приоритет №1) и Югры, убирает дубли и уведомляет редактора в Telegram.

**Срок:** хакатон, TODO часов. Важнее работающий сквозной сценарий на реальных данных, чем полнота функций.

## Что должно работать (обязательный минимум)

1. **Сбор** — RSS, сайты без RSS (HTML), публичные Telegram-каналы, стены VK.
2. **Отбор** — фильтрация по географии и темам, удаление дублей, выделение новых событий, оценка важности.
3. **Уведомление** — сообщение редактору в Telegram: заголовок, краткая суть, источник, ссылка, время, важность.

**Бонус (после минимума):** веб-админка с настройкой источников и приоритетов, история находок, статистика обратной связи.

## Стек (не меняй без согласования)

- Python 3.11+
- `httpx` (async) — запросы; `feedparser` — RSS; `selectolax` или `beautifulsoup4` — HTML; `trafilatura` — извлечение текста статьи
- Telegram-каналы — парсинг веб-превью `https://t.me/s/<channel>` (без Telethon, без пользовательского аккаунта)
- VK — официальный API, метод `wall.get` (токен в `.env`)
- `APScheduler` — планировщик
- SQLite через `SQLAlchemy 2.x` (схема должна переноситься на Postgres без переписывания)
- `sentence-transformers`, модель `intfloat/multilingual-e5-small` — эмбеддинги для поиска дублей (локально)
- LLM — через абстрактный клиент (см. ниже); основной провайдер — **Polza.ai** (OpenAI-совместимый агрегатор, официальный SDK `openai` с `base_url`)
- `aiogram 3.x` — Telegram-бот
- `Streamlit` — админка (бонус)
- `pydantic` — валидация ответов LLM и конфигов
- `docker-compose` — запуск одной командой

## Модель данных

- **sources**: id, name, type (`rss|html|telegram|vk`), url/handle, geo (`surgut_city|surgut_district|khmao`), priority (1–3), enabled, parser_config (JSON: селекторы для html), last_success_at, last_error, error_count
- **raw_items**: id, source_id, external_id, url, published_at, fetched_at, title, text, content_hash (уникальный), status (`new|filtered_out|analyzed|error`)
- **analyses**: raw_item_id, весь JSON ответа Промта 1, model, prompt_version, created_at
- **events**: id, headline, summary, key_facts, geo_level, topic, max_importance, first_seen_at, last_updated_at, embedding, telegram_message_id
- **event_items**: event_id, raw_item_id, relation (`origin|duplicate|update`), new_facts
- **feedback**: event_id, user_id, action (`take|skip|in_progress`), created_at
- **notifications**: event_id, sent_at, type (`new|update`), telegram_message_id

## Требования к модулям

### Сборщики
- Каждый источник обрабатывается независимо: таймаут 15 с, 2 повтора с паузой, падение одного источника не останавливает остальные. Ошибки пишутся в `sources.last_error` и в лог.
- Параллельность ограничена (семафор, например 10).
- Нормальный User-Agent, без агрессивной частоты запросов.
- Новизна определяется по `external_id`/URL и `content_hash` — один пост не попадает в базу дважды.
- При первом запуске источника не обрабатывать всю историю: брать материалы не старше `INITIAL_LOOKBACK_HOURS` (по умолчанию 24).
- Для HTML: список ссылок на странице-ленте по селектору, затем текст статьи через `trafilatura`.

### Предфильтр (без LLM, дёшево)
- Отбросить: пустые и слишком короткие тексты (< `MIN_TEXT_LEN`), материалы старше `MAX_AGE_HOURS`, точные дубли по хэшу.
- Опционально: стоп-слова из конфига (реклама, розыгрыши).
- Не фильтровать по слову «Сургут» — географию решает LLM.

### LLM-анализ
- Промт 1 из `prompts/`, ответ валидируется pydantic-схемой. Если JSON невалиден — один повтор с сообщением об ошибке, затем `status=error` и лог.
- `prompt_version` сохраняется вместе с ответом.
- Провайдер выбирается в `.env` (`LLM_PROVIDER`, `LLM_MODEL`, ключи). Переключение провайдера не должно требовать правки кода.
- **Основной провайдер — Polza.ai.** Он совместим с OpenAI SDK, поэтому используй `openai_compat.py`:
  ```python
  from openai import AsyncOpenAI
  client = AsyncOpenAI(base_url=settings.LLM_BASE_URL, api_key=settings.LLM_API_KEY)
  # LLM_BASE_URL=https://polza.ai/api/v1
  ```
  Идентификаторы моделей в формате `провайдер/модель` (например, `openai/gpt-4o-mini`, `deepseek/deepseek-chat`). Актуальный список: `GET https://polza.ai/api/v1/models?type=chat`. Модель задаётся только через `LLM_MODEL`, в коде не хардкодить.
- Ключ берётся **только** из переменной окружения `LLM_API_KEY` (файл `.env`). Ключ никогда не пишется в код, логи, README, тесты и не коммитится.
- Логировать расход: токены на запрос и за цикл, чтобы видеть стоимость.

### Дедупликация
- Эмбеддинг от `headline + summary` (префикс `query:` для e5).
- Кандидаты: события за последние `DEDUP_WINDOW_HOURS` (48) с косинусной близостью ≥ `DEDUP_SIM_THRESHOLD` (стартово 0.85, вынести в конфиг), top-5.
- Нет кандидатов → новое событие без вызова LLM. Есть → Промт 2 решает `duplicate|update|new_event`.

### Уведомления
- Правила в `notify_rules.py`, пороги в конфиге:
  - отправлять, если `is_relevant` и `importance >= 3` (для `surgut_city` — `>= 2`);
  - `urgency=breaking` и `importance >= 4` — пометка 🔴;
  - `update` — ответом (`reply_to`) на исходное сообщение события; `duplicate` — не отправлять.
- Формат сообщения и кнопки — как в `radar_prompts.md`. Кнопки пишут в `feedback` и меняют сообщение (например, добавляют «✅ Взято в работу»).
- Команды бота: `/start`, `/status` (сколько источников живо, последний цикл, ошибки), `/today` (сводка за день).
- Защита от флуда: не больше `MAX_NOTIFICATIONS_PER_CYCLE` за цикл, остальное — одной сводкой.

### Админка (бонус, Streamlit)
- Источники: список, включить/выключить, приоритет, статус (последний успех, ошибка), добавить новый.
- История: таблица событий с фильтрами (дата, география, тема, важность, реакция редактора), ссылки на все источники события.
- Статистика: событий за день, доля 👍/👎, самые полезные и самые «шумные» источники.

## Нефункциональные требования

- Все секреты — только в `.env`, в репозитории `.env.example`. `.env` добавить в `.gitignore` на этапе 1.
- `.env.example` должен содержать как минимум:
  ```
  LLM_PROVIDER=openai_compat
  LLM_BASE_URL=https://polza.ai/api/v1
  LLM_API_KEY=your_polza_key_here
  LLM_MODEL=openai/gpt-4o-mini
  TELEGRAM_BOT_TOKEN=
  TELEGRAM_EDITOR_CHAT_ID=
  VK_TOKEN=
  ```
- Логи в структурированном виде: время, источник, этап, результат.
- Запуск: `docker compose up` поднимает сборщик+бот и админку.
- Скрипт `python -m radar.run_once` — один полный цикл с подробным выводом (для отладки и демо).
- Скрипт `python -m radar.eval --file calibration.csv` — прогон Промта 1 по размеченному набору, вывод precision/recall по `is_relevant` и средней ошибки по `importance`.
- Тесты: парсеры на сохранённых HTML/RSS-фикстурах (без сети), валидация JSON-ответов LLM, правила уведомлений.
- README: как запустить, как добавить источник, как сменить LLM-провайдера.

## Порядок работы

Работай по этапам. **После каждого этапа остановись, покажи, что сделано и как проверить, и дождись подтверждения.**

1. **Каркас**: структура проекта, конфиг, модели БД, загрузка `sources.yaml`, docker-compose, README-заготовка.
2. **Сбор**: RSS и Telegram (`t.me/s`) + `run_once`, который сохраняет сырые материалы. Проверка на 3–5 реальных источниках.
3. **Анализ**: LLM-клиент (OpenAI-совместимый), Промт 1, валидация, сохранение.
4. **Уведомления**: бот, отправка по правилам, кнопки обратной связи. **На этом этапе должен работать сквозной сценарий — это главный чекпоинт.**
5. **Дедупликация**: эмбеддинги, Промт 2, обновления ответом на сообщение.
6. **HTML и VK** сборщики.
7. **Планировщик** каждые 15 минут, `/status`, защита от флуда.
8. **Админка** (бонус) и `eval`.

## Критерии готовности к демо

- Система работает непрерывно минимум TODO часов на TODO+ реальных источниках без падений.
- Редактор получает в Telegram уведомления с заголовком, сутью, источником, ссылкой, временем и важностью.
- Одно событие из нескольких источников приходит одним сообщением, обновления — ответом на него.
- Падение одного источника видно в `/status` и не ломает остальное.
- Есть журнал находок с временем обнаружения, чтобы сравнить со временем публикации на siapress.ru.
